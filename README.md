# Финансы — Android

Приложение на React Native и TypeScript: личные счета, депозиты, кредиты, доходы, расходы и ежемесячные обязательства. Интерфейс на русском языке, единственная валюта — тенге. Оформление следует присланным образцам: серый фон, белые карточки, голубые акценты, формы и цифровая клавиатура.

## Статус

Приложение собрано пользователем в release APK и установлено на Android через ADB. Пользователь подтвердил работу приложения. Автоматические тесты, линтеры и проверки TypeScript не запускались. Текущий интерфейс сохранён; редизайн планируется отдельно.

Подключена конфигурация Firebase-проекта `finance-35d35`, Android package name — `com.nodata.finance`. Публичное название проекта в Google Authentication — `Finance Android`. Файл `google-services.json` предоставлен заказчиком и размещён в `android/app/`; он исключён из Git. 4 ноября 2026 года через авторизованный Firebase CLI добавлены SHA-1 и SHA-256 debug-сертификата, затем заново загружена актуальная конфигурация. Правила `firestore.rules` успешно опубликованы в базе `(default)` этого проекта командой `deploy --only firestore:rules`; серверная компиляция правил прошла в рамках публикации. Приложение при этом не запускалось и не собиралось. При отсутствии конфигурации приложение показывает сообщение о незавершённом подключении облачного сервиса.

## Подключение Firebase

1. Android-приложение зарегистрировано с package name `com.nodata.finance` в Firebase-проекте `finance-35d35`.
2. В Firebase Authentication включить Google.
3. Создать Cloud Firestore Standard, базу `(default)`.
4. Сохранить актуальный `google-services.json` в `android/app/google-services.json`. Этот файл исключён из Git. При отсутствии файла Google Services Gradle plugin не применяется.
5. В Firebase Console → Firestore → Rules вставить содержимое `firestore.rules` и опубликовать. Правила запрещают доступ к чужому UID и любые непредусмотренные пути. Начальные Production rules, запрещающие все обращения, необходимо заменить именно этими правилами.
6. Добавить SHA-1 сертификата используемого Android-приложения в Firebase → Project settings → Android. Для конфигурации выпуска использовать отпечаток сертификата выпуска, при Google Play App Signing — сертификата подписи приложения в Google Play. После изменения OAuth-конфигурации снова скачать `google-services.json`.
7. Web OAuth Client ID читается библиотекой входа автоматически из Android-ресурса `default_web_client_id`, создаваемого Google Services plugin. Нужен клиент типа Web (`client_type: 3`), а не Android Client ID.

Отпечатки сертификата разработки из `android/app/debug.keystore`:

```text
SHA-1:   5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25
SHA-256: FA:C6:17:45:DC:09:03:78:6F:B9:ED:E6:2A:96:2B:39:9F:73:48:F0:BB:6F:89:9B:83:32:66:75:91:03:3B:9C
```

Оба отпечатка уже добавлены в Firebase для Android App ID `1:110079765363:android:8ea0fa68f8da4dcdb93306`. Это отпечатки только debug-сертификата. Для подписанного выпуска нужно добавить отпечатки его собственного сертификата. Отпечатки получены чтением keystore через `keytool`, без Gradle и без сборки приложения.

Коллекции создавать вручную не нужно. После первого входа приложение одной транзакцией создаёт профиль, настройки и базовые категории. Приватный ключ сервисного аккаунта в мобильном приложении не используется.

Для текущих запросов составные индексы не нужны: `firestore.indexes.json` содержит пустой список. У пользователя подписки на свои коллекции; агрегирование выполняется локально. При очень большой истории следующим этапом можно добавить серверные агрегаты и постраничные запросы. На экране история показывается порциями, экспорт получает всю историю с сервера.

Версии зависимостей закреплены в `package.json` и `package-lock.json`. Для установки используйте `npm ci`. Тестовые скрипты и тестовые проекты не добавлены.

Android wrapper и общедоступный debug keystore взяты из официального `@react-native-community/template@0.88.1`. Debug keystore предназначен только для разработки. Для подписи release используются переменные окружения `FINANCE_KEYSTORE_PATH`, `FINANCE_KEYSTORE_PASSWORD`, `FINANCE_KEY_ALIAS`, `FINANCE_KEY_PASSWORD`. Приватный release-ключ и конфигурация `google-services.json` хранятся локально и исключены из Git. Команда сборки из корня проекта: `.\android\gradlew.bat -p .\android assembleRelease`.

## Правила учёта

- Все суммы в Firestore — целые числа в тиынах. 1000 ₸ хранится как 100000. Поля формы принимают не больше двух знаков после запятой. Калькулятор поддерживает сложение, вычитание, умножение и деление, округляя результат до тиына.
- Первые вкладки: «Счета», «Расходы», «Доходы». При входе открываются «Счета». Все дополнительные страницы находятся в меню.
- Банковские счета и депозиты создаются с названием и начальным остатком. После создания изменяются название и комиссия. Начальный остаток напрямую не редактируется и не входит в доходы.
- Кредиты автоматически называются «Кредит 1», «Кредит 2» и далее. Номер не переиспользуется. У кредита есть оставшийся долг, ежемесячный платёж, число платежа и банковский счёт погашения. Числа 29–31 в коротком месяце отображаются последним днём месяца.
- Все действия ручные. В приложении нет банковской интеграции и автоматического списания. Погашение уменьшает баланс банковского счёта и оставшийся долг. Проценты отдельно не учитываются. Досрочное погашение возможно, сумма не может превышать долг.
- Капитал = средства на банковских счетах и депозитах − оставшийся долг. Погашение основного долга не создаёт дополнительного расхода в статистике. Комиссия уменьшает средства и учитывается расходом.
- Перевод 1000 ₸ с комиссией 150 ₸ создаёт отдельные записи списания 1000 ₸, комиссии 150 ₸ и зачисления 1000 ₸. Все записи и оба баланса сохраняются одной Firestore-транзакцией. При недостатке денег с учётом комиссии действие отклоняется целиком.
- В доходах и расходах кнопка «+» рядом с категорией предвыбирает её. В форме можно выбрать ручную операцию либо перевод. Перевод не увеличивает доходы и расходы; комиссия относится к категории «Комиссия за переводы».
- Дата операции — календарная дата устройства, по умолчанию сегодня; можно выбрать прошедшую дату. Даты будущих фактических операций не допускаются. Неделя начинается с понедельника, кварталы календарные. Фильтр по умолчанию — текущий месяц.
- Счёт по умолчанию задаётся в настройках. В режиме «Спрашивать каждый раз» выбор пустой до явного указания счёта. У кредита свой предвыбранный счёт погашения, который можно изменить для конкретного платежа.
- Обязательства — служебная категория отдельно в доходах и расходах. Каждое обязательство является подкатегорией с названием, суммой и описанием. Выбор подставляет сумму и комментарий. Сумму фактической операции можно изменить.
- Выполнение обязательства определяется парой «обязательство + месяц даты операции». Отметка создаётся атомарно с операцией, повторное выполнение того же обязательства за тот же месяц отклоняется, в том числе при одновременной записи с двух устройств. В следующем месяце ничего не удаляется: приложение показывает новую месячную отметку как отсутствующую.
- Лимиты — ежемесячные, превышение не запрещает расход. Лимит категории расходных обязательств равен сумме активных обязательств. Исполнение не уменьшает лимит. В строке лимита отображаются траты текущего месяца, даже если основной фильтр экрана выбран иначе.
- Удаление категории скрывает её из новых операций и сохраняет историю. В статистике выбранного периода удалённая категория остаётся, если по ней есть операции. Обязательства и комиссия — служебные категории; их системные названия сохраняются.
- Счёт нельзя удалить с ненулевым остатком, кредит — с оставшимся долгом. Счёт погашения нельзя удалить, пока он выбран в действующих кредитах. Удаление не стирает исторические записи. При удалении счёта по умолчанию включается режим «Спрашивать каждый раз».
- На диаграмме счетов показаны доли положительных средств. Долг и капитал вынесены отдельно, чтобы отрицательные величины не искажали круговую диаграмму. При отсутствии данных показывается нейтральное кольцо.
- Операции сохраняют название счёта, категории и обязательства на момент записи. Журнал операций неизменяемый; отдельный сценарий исправления проведённых операций не реализован, поскольку его правила не были согласованы отдельно.

## Данные Firestore

```text
users/{uid}
  accounts/{accountId}
  categories/{categoryId}
  obligations/{obligationId}
  completions/{obligationId_YYYY-MM}
  operations/{operationId}
  settings/main
```

Одна операция может содержать несколько записей `entries`. История и экспорт отображают каждую запись. Повторная отправка той же формы использует тот же `operationId`. Изменения баланса связаны через `lastOperationId` с новой операцией; правила Firestore сопоставляют изменение остатка с её записями. Опубликованные правила должны соответствовать этому формату.

## Экспорт

В меню → История → Экспорт доступны PDF, настоящий Excel `.xlsx` и CSV. Экспорт всегда получает все операции пользователя с сервера, независимо от фильтра и количества отображаемых строк. Поэтому для экспорта нужен интернет.

CSV: UTF-8 с BOM, разделитель `;`, дробная запятая; текстовые значения защищены от интерпретации как формулы. В Excel суммы записаны числовыми ячейками. PDF содержит экранированный текст и повторяемые заголовки таблицы. Файл передаётся в системное меню Android, где пользователь выбирает приложение или сохранение. Созданные файлы находятся в кэше приложения; копии старше суток удаляются при следующем экспорте.

Существующие шаблонные файлы wrapper распространяются на условиях их исходной лицензии; лицензия React Native Community Template сохранена в `android/TEMPLATE-LICENSE`.
